# 从产品数据点设计 Android 控制页

本文件用于 Android 产品 App 的控制页面。目标是开发者产品的正式交互，不是数据点调试器。可以复用按钮、卡片等基础组件，不能继续按 boolean/number/enum/binary 遍历生成一排通用控件，或只换颜色和标题。

## 取得并解释真实协议

在正确组织下查询产品名称、类别和描述，保存数据点定义和协议导出：

```bash
python3 "$SKILL_DIR/scripts/gizwits.py" --org <组织ID或personal> product <PK>
python3 "$SKILL_DIR/scripts/gizwits.py" --org <组织ID或personal> datapoints <PK> --out product-meta.json
python3 "$SKILL_DIR/scripts/gizwits.py" --org <组织ID或personal> export-json <PK> --out product-protocol.json
```

按已选 PK 核对两份文件。meta 提供显示名、描述、权限和量程等业务信息，protocol 提供 SDK 对应的协议定义；不要将 Excel 直接喂给 SDK。如需打包离线协议，先核对当前 SDK 的文件名和格式；`MainActivity.copyAssetsToCustomDirectories()` 仅在文件不存在时复制，升级协议不能依赖旧文件自动被替换。

为实现维护一份简明映射（项目文档或代码旁），每个使用的数据点记录：实际字段名、业务语义、读写权限、类型、单位、合法值/枚举顺序、缩放、关联条件、页面位置、命令和回报判断。未知业务语义优先读说明，只向开发者补问确实无法推断的含义；在确定前禁用有关控制，不猜 binary 协议或命令副作用。无权限/网络失败不能当“没有数据点”，更不能退回生成虚构控件。

权限遵循云端 `perm`（W/R/N/E）及 SDK 对应状态：只有可写点提供操作；只读状态显示，告警/故障做提示。区分“设定温度”和“实测温度”、目标状态与实际状态。枚举显示业务标签，发送协议真实值及顺序，不能按翻译后排序重建索引。

数字范围先明确 SDK 收发的是业务值还是原始计数。当前 demo 的 NumberDataPointState 按业务值处理，使用 ratio/addition 与 minCount/maxCount 计算量程及步进；不要额外缩放两次。核对当前 SDK 后按实际分辨率量化、校验边界，单位和小数位一致。binary 必须有明确业务编码、长度和字节顺序，不能把裸十六进制输入框当产品功能。

## 设计并实现业务页面

结合品类、数据点和开发者要求，先形成短设计说明：主状态是什么、最高频的操作是什么、设置如何分组、哪些异常需置顶，然后直接实现。明确要求已足够时不额外设置设计审批关卡。

以下只是布局思路，只有实际数据点支持才使用：

| 产品场景 | 页面组织 |
|---|---|
| 温控/空调 | 当前温度与运行状态为主信息；目标温度调节为主操作，模式/风速按运行模式联动，故障单独提示。 |
| 照明 | 电源、亮度和色温组成灯光操作区；有颜色协议才提供色彩选择，有场景协议才提供场景。 |
| 风扇/净化器 | 风速或空气状态为主，电源、模式、档位为直接操作；滤芯/定时按真实点分组。 |
| 窗帘 | 开/停/关和当前位置形成一组；行程设置作为次级操作，不能把目标位置当作实时位置。 |

将 SDK 连接/读写封装在状态层，提供业务命名的 UiState 和动作（例如 setTargetTemperature），Compose 页面显式组合产品布局。多产品用经过核对的 PK → 页面/适配器映射；未知产品显示不支持或协议不匹配，不回退到通用数据点列表。优先显示用户理解的状态，不把 MQTT/LAN/BLE 选择器作为首页主要任务。

保留 demo 已实现的底层能力：`ControlDataViewModel` 中的 `subscribeStatus()`、`subscribeDp()`、`getDp(null)`、`sendDp(...)`、增量快照合并和取消处理可作为迁移依据；替换其 `uiState` 按 DataPointType 构造通用控件的部分。SDK 函数签名以克隆版本为准，不能假定存在自动路由或原子多点发送 API。

需要多通道时，为实际产品确定通道策略：只在真实支持且 ONLINE_CONTROLLABLE 的能力上读写，将订阅状态与发送通道对应，防止旧通道回报覆盖新会话状态。命令发送结果不明时先读回，不跨通道盲目重发不可重复命令；不支持的蓝牙/局域网能力不做虚假入口。

## 正确反馈设备状态

- 页面区分未知、加载、在线、离线、最后状态、发送中、已确认和失败；未收到值显示未知，不以 false/0 假造状态。缓存按设备及身份隔离，离线缓存带最后更新时间。
- `sendDp` 成功只证明请求接口成功，不代表执行成功。参照 `sendAndReadDataPoint` 写后读回，并结合订阅回报判断实际状态；读回失败显示“已发送，状态待确认”，目标与回报不一致时也不能标成成功。
- 滑动调整时显示本地草稿，在松手或合理节流后发送；忙碌和离线时限制操作，失败保留最后确认值并提供重试，不把草稿写进真实状态缓存。
- 只合并回报中实际出现的字段，缺字段不归零；页面重建不重复发命令。订阅跟随生命周期释放；同一设备的新回报更新 UI，旧设备/旧身份异步结果不能更新当前页。
- 模式联动由协议业务定义决定；不能仅靠控件隐藏实现约束，发送层也检查可写性、合法范围、枚举值和设备可控状态。多点操作部分失败要明确反馈，不能声称事务成功。

验证映射中的真实动作：枚举映射、量程与步进、只读不发指令、状态未知/离线、写失败、写成功但读失败、设备拒绝或返回不同值、增量回报和跨设备隔离。界面检查布局层级、触控与字体可读性、长文案、异常提示；交付截图或可运行预览并标注模拟状态，不能把预览当真机控制验证。
