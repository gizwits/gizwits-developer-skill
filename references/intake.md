# 需求询问与资源选择

用于进入产品接入、固件开发或 App 开发前，决定复用哪些资源、需要补建哪些资源。这里只定义判断流程，具体命令与字段见 [接口与命令](api.md)。用户只要求查询、导出或修改某一项时，直接处理该项，不强行收集完整项目资料。

## 先了解已知内容，再补问

从当前对话、已选组织、用户指定工程和已有配置中辨认任务目标及资源标识；本地凭据只核对，不回显。信息已足够就查询核实，不重复问“有没有产品和 App”。以下问题按缺项选择，不一次发整份问卷：

- 不清楚资源情况时：“这次使用已有的产品和 App，还是需要我帮你创建？也可以只创建其中一个；不确定的话我登录后帮你查。”
- 所属空间不明且有多个选择时：“这次在个人空间，还是哪个组织下开发？”结合查询结果提供相关名称，不倾倒全部组织列表，也不默认选择第一个组织。
- 开发者说已有时，名称、PK、AppID、package id/code 或已有工程任一线索即可，不强制其找齐所有标识；先检索并补全。
- 新建确有缺项时，集中询问本阶段缺少的名称、包名或产品能力，已经说过的不用再问。任务明确为 Android 时平台直接用 Android，不额外询问 iOS/Harmony。

首次需要调用开发者中心时按 [登录与会话](auth.md) 引导登录或复用会话。先确定所选空间，再查询该空间的 `products` 和 `apps`；具备明确标识时优先查详情。以名称匹配出现多个候选时，用名称、PK/AppID、包名、产品状态帮助选择。AppID 须反查到相应平台与 package，不能当 package id 直接调用详情接口。

## 分支处理

| 开发者当前情况 | 下一步 |
|---|---|
| 产品、App 都已有 | 核对两个对象和平台，复用其标识及凭据；查询关联，按接入任务补关联，不重建。 |
| 只有产品 | 读取已有数据点；App 开发需要时创建 App，再关联已有产品。仅固件开发可直接继续。 |
| 只有 App | 复用 App，询问新产品的业务与通信需求，创建产品并定义数据点，再关联该 App。 |
| 两者都没有 | 按目标创建所需资源：固件只需产品；Android 接入需要产品和 App。名称/包名/协议需求齐全后直接执行。 |
| 不确定或只记得名字 | 查询已有列表及详情，展示少量相关候选供辨认；在所选空间成功完成查询仍无匹配时，询问是否新建，或按开发者已明确的“没有就帮我建”继续。 |

“没有提供 PK/AppID”不等于“资源不存在”。没有 PS/App Secret 只说明凭据待补，不重建资源或重置密钥。403、网络失败、分页未读完、空间选错不能作为不存在的证据；开发者明确说已有但未查到时，先核对空间、名称和权限，不能擅自改成新建。跨空间资源不自动迁移或在另一空间复制，先明确此次应使用的组合。

已有 App 没有 Android 平台配置时，不冒用 iOS AppID，也不直接创建同名 App；先检查该 App 的补平台能力与权限。当前 CLI 未提供此操作时说明缺项，使用经核实的接口或开发者中心入口补齐，不能编造 API。

## 新建时只收集必要业务信息

**产品**：产品名称、用途/品类、通信方式（例如 Wi-Fi、BLE、Wi-Fi+BLE），以及会影响创建字段的网关/子设备等特征。先查询有效品类，能够从明确用途唯一匹配时直接选择；有歧义才问。始终创建变长模式，不询问协议定长或变长。芯片型号是固件任务另需的信息，不用它代替通信方式。

**App**：名称、实际包名和所需平台；已有目标工程可读取包名线索，但不默认把模板演示包名当开发者自己的包名。用户体系关联仅在确有此需求时收集。使用 API 文档要求的字段，不能把示例名称、包名或类别 ID 直接用于真实创建。

**数据点**：已有产品先读取定义，以现状继续；不存在数据点时询问产品要控制什么、上报什么、单位/量程、模式及告警。先根据需求整理定义，只有影响编码或业务行为且无法确定的部分才补问，再按 Excel 流程校验、导入和回读。已有部分定义时保留它们，必要的扩展遵循原流程；新建产品成功不等于数据点已就绪。缺业务信息期间可准备工程和工具链，但不能用样例点代替真实协议。

创建前再次按名称/包名检查冲突。出现同名对象时辨别它是不是本次要用的对象；不能自动选第一个，也不能为绕过脚本的去重检查偷偷改名。开发者已要求“帮我创建”或“没有就创建”且参数齐全时不再加一轮许可确认。

## 衔接后续开发

简短告知最终选择，例如：“复用组织 A 的产品 X，创建 Android App Y，沿用现有 8 个数据点，补齐两者关联后开始开发。”这是执行说明，不是额外审批。记录当前空间、产品 PK、package id/code、对应平台 app_id、关联结果及待补项；不记录明文 Secret。

每个创建/导入/关联步骤成功后查询核对。中途失败保留已经成功的资源及标识，继续补未完成部分；创建请求结果不明先查状态，不从头重建。完成资源准备后，将同一产品协议用于固件和 Android 控制页，把正确平台的 App 凭据交给 Android 工程，避免两端各自选了不同产品。
